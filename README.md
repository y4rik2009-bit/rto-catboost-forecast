# Прогноз месячного РТО с CatBoost

Портфолио-проект: прогноз розничного товарооборота (РТО) объекта на следующий месяц по его истории и характеристикам. Сравниваются простой прогноз «следующий месяц как текущий», линейная регрессия и CatBoost. Гиперпараметры CatBoost подбираются Optuna по ошибке на более поздних месяцах.

## Данные и доступность

Скрипт ожидает **собственный, полученный законным образом** файл `data/train_2.csv` в кодировке UTF-8. Исходный датасет в репозиторий не входит; его публичный статус и право на распространение не подтверждены. Поэтому воспроизвести численные результаты без доступа к данным нельзя. Структура файла описана в [DATA_FORMAT.md](DATA_FORMAT.md).

В исходном файле каждая строка — один объект за один месяц. Для каждого `new_id` нужны 26 последовательных месяцев: январь 2023 — февраль 2025. Известный РТО февраля 2025 используется для прогноза марта 2025. Если исходные данные отличаются, сначала проверьте схему и временные границы в коде.

## Метод

1. Числовые пропуски заполняются средним, вычисленным только по обучающим месяцам; категориальные — значением `Неизвестно`. РТО логарифмируется, поэтому он должен быть положительным.
2. Цель каждой строки — логарифм РТО того же объекта в следующем месяце.
3. Обучение: признаки месяцев 1–21 (январь 2023 — сентябрь 2024); валидация: 22–23 (октябрь — ноябрь 2024); тест: 24–25 (декабрь 2024 — январь 2025). Целевые месяцы сдвинуты на месяц вперёд.
4. Optuna делает 50 новых попыток за запуск, сохраняет исследование в `outputs/optuna_logged_rmse.db`. Затем CatBoost обучается с лучшими параметрами и ранней остановкой по валидации.
5. Скрипт печатает MAPE в исходной шкале РТО (доля: `0.10` означает 10%) и RMSE в шкале логарифма. `outputs/test.csv` содержит **прогноз марта 2025**, а не оценки тестовой выборки.

## Запуск на компьютере

Нужен Python 3.12 и место для датасета и результатов. Команды ниже — для PowerShell в корне проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
New-Item -ItemType Directory -Force data | Out-Null
# Поместите разрешённый к использованию train_2.csv в папку data вручную.
.\.venv\Scripts\python.exe train.py
```

На других системах используйте `python3.12 -m venv .venv`, затем Python из созданного виртуального окружения. Первая установка пакетов требует интернета. Полный подбор 50 моделей может занять значительное время.

По умолчанию используется CPU. GPU **не обязателен**; при наличии совместимого NVIDIA GPU и драйвера задайте переменную окружения перед запуском:

```powershell
$env:CATBOOST_TASK_TYPE = "GPU"
.\.venv\Scripts\python.exe train.py
```

В Google Colab можно загрузить файлы проекта и разрешённый CSV, установить зависимости командой `!pip install -r requirements.txt`, положить CSV в `data/` и запустить `!python train.py`. Для GPU выберите ускоритель GPU в настройках среды и запустите `!CATBOOST_TASK_TYPE=GPU python train.py`. Google Drive не требуется. Файлы временной среды Colab исчезнут после завершения сеанса, поэтому нужные результаты скачайте вручную. Не публикуйте исходный CSV вместе с блокнотом.

## Результаты и ограничения

Подтверждённых численных значений метрик в этом репозитории пока нет: полный запуск Optuna и итоговой модели не выполнен для публикации. После собственного полного прогона можно добавить сюда датированную таблицу с MAPE базовых моделей, MAPE и RMSE CatBoost, устройством CPU/GPU и версиями пакетов. Не сравнивайте напрямую RMSE логарифма с MAPE в исходных единицах.

Данные и признаки могут содержать сведения об отдельных объектах. Право на их публикацию нужно проверить отдельно. Код жёстко рассчитан на 26 месяцев указанного периода и не служит готовой системой для произвольного датасета. CPU и GPU, а также повторные запуски GPU, могут дать разные модели. Повторный запуск добавит ещё 50 попыток Optuna к сохранённому исследованию; если данные или схема изменились, удалите локальную базу `outputs/optuna_logged_rmse.db` перед новым исследованием.
